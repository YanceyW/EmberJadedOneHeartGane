# ADR-0010：WebGL 粒子层（未决）

- 状态：**未决**（待真机数据）
- 日期：2026-11

## 背景

需求里提到「细节粒子给 GPU」。但一个 canvas 只能有一个上下文，
主画布已固定为 Canvas 2D（ADR-0005），因此只有两条 GPU 路线：

1. **换 WebGL 主渲染**：等于重写整套绘制代码，风险极高；
2. **额外 WebGL 离屏画布 + 每帧 `drawImage` 合成**：可行，但每帧多一次全屏拷贝。

## 目前结论

先用 ADR-0008 的 Canvas 2D 方案（实测 240 粒子在中端机 60fps、低端 120 粒子可玩），
**不阻塞在 GPU 上**。

## 何时重新评估

满足任一条件时，做一次真机对照实验再决定：

- 单屏粒子需求稳定 > 400；
- 出现 Canvas 2D 无法表达的效果（软体、流体、光照）；
- 低端机粒子降到 120 后仍掉帧。

## 实验方法

- 同一屏、同一粒子数，对比两种实现的**每帧耗时**（P50/P95）与**内存**；
- 设备：低端安卓（benchmarkLevel < 10）、中端安卓、iPhone SE；
- 只有「中端 60fps 且低端不掉档」才考虑替换。

## 约束

- 未拿到数据前不得引入 WebGL 依赖；
- 若替换，必须保留 Canvas 2D 回退路径。
