# ADR-0023：王都仓库 + 餐厅三线 + 每日委托

- 状态：**已采纳**（取代 ADR-0022 里「餐厅 3 窗口上菜」与「食材只有 8 种」的部分）；**部分被 [ADR-0024](./ADR-0024-restaurant-composition-and-ranch.md) 与 [ADR-0025](./ADR-0025-stove-patterns-and-endless-shift.md) 取代**（餐厅改为备料台 + 3×3 灶眼图案，新增牧场与牧产，营业改为无时限品质结算）
- 日期：2026-02
- 相关：[ADR-0018 农场即食材玩法](./ADR-0018-farm-as-ingredient-game.md)、[ADR-0021 花园/加工屋/水族馆可玩](./ADR-0021-playable-garden-merge-aquarium.md)、[ADR-0022 仓库与产业链](./ADR-0022-pantry-chain-and-unlimited-endless.md)

## 背景

ADR-0022 把「食材」搬进了 `profile.pantry`，但当时只有 8 种作物 + 2 种半成品，出口只有餐厅的 3 个窗口。实际玩下来有三个问题：

1. **看不见**：仓库里的东西只能在各馆页面里零散看到，玩家不知道自己攒了什么、值多少钱，也没法主动清理。
2. **产业链只有一条腿**：餐厅「上菜」直接吃食材，玩家一晚上就把攒的料掏空；而且做菜没有「慢慢来」的节奏，跟种地的时间成本对不上。
3. **内容太薄**：8 种作物撑不起「种地 → 加工 → 做菜」的中式餐桌想象，仓库也没有存在感。

## 选项

### A. 只加一个只读仓库面板

- 优点：改动最小。
- 缺点：仍然没有出口，仓库只是一个更大的数字堆；餐厅照样会掏空食材。

### B. 仓库 + 多选卖出（本次采纳的第一步）

- 优点：玩家能主动把囤货换成币，仓库成为「资产总览」。
- 缺点：只有卖，产业链没有增值环节，仍然缺少长期目标。

### C. 仓库 + 多选卖出 + 采购补齐（采纳）

- 优点：缺料时能立刻继续玩，不用等作物成熟；采购价 = 卖价 × 3，天然不划算，只是救急。
- 缺点：需要一条「采购一定亏」的价格不变量，否则会变成套利。

### D. 餐厅拆成三条线（采纳）

- **厨房（备菜）**：吃原料，产出成品进仓库；
- **点菜**：吃成品，卖菜价（88–186 币），是产业链真正的出口；
- **营业（端盘子小游戏）**：用吧台的免费简餐，按件数 + 小费 + 连击算营业额，**不读写仓库**。

### E. 每日委托（采纳）

- 每天 3 单，来自「面馆补货 / 花店补花 / 茶馆要茶」等固定池，按日期确定性抽取；
- 必须手动点「交付」才扣货结算；
- 3 单全清有额外奖励并累计连续天数。

## 决策

同时采纳 C + D + E，并把内容量一次性拉够：

| 类别 | 数量 | 说明 |
|---|---|---|
| 作物 | 18 | 小白菜 → 葡萄，种价 6–28、成熟 20–120 秒、卖价 12–58 |
| 花卉 | 9 | 雏菊 → 荷花，全部进仓库（花园不再自建库存） |
| 半成品 | 11 | 面粉 / 米粉 / 挂面 / 豆腐 / 玉米面 / 蒜蓉 / 面包 / 馒头 / 酸菜 / 豆沙 / 菌菇高汤 |
| 茶饮 | 5 | 米浆 / 豆浆 / 茉莉花茶 / 菊花茶 / 桂花茶 |
| 成菜 | 18 | 分 3 个厨房分页（炒菜 7 / 主食 5 / 点心 6），菜价 88–186 |
| 鱼 | 8 | 小金鱼 → 龙鱼，60–460 币 |

配套约束：

- **只有王都币**，不新增第二种货币；
- 货物目录与价格**只在** `src/shared/content/ingredients.ts` 定义，其它模块引用不复制；
- 采购价 = `ceil(sellPrice × 3 / 5) × 5`；
- 仓库面板 5 个分页（作物 / 花卉 / 半成品 / 茶饮 / 成菜），支持多选卖出与全选/清空；
- 库房是**街区设施**（`facilities`），不是分包游戏，不参与排行榜与场馆加载。

## 经济不变量（由测试锁定）

1. 半成品卖价 < 原料卖价之和（做加工不亏时间但不多赚）；
2. 菜价 > 食材卖价之和（做菜是真正的增值）；
3. 成菜仓卖价 = 菜价 × 0.4，且 < 食材卖价之和（不能「做了再卖」套利）；
4. 全采购做一道菜一定亏（采购价 ≥ 菜价 × 1.2 以上）；
5. 营业页不读写 `pantry`（单测直接断言）；
6. 每日委托同一日期同一结果，不点「交付」不扣货。

## 后果

- **正面**：仓库成为资产总览与出口；餐厅有了「慢做 / 快卖 / 小游戏」三种节奏；内容量足够支撑 6 个场馆各有存在感。
- **负面**：`ingredients` 从 10 条涨到 61 条，`goods-art` 随之增大（约 1000 行绘制代码），需要分页渲染控制单帧负担。
- **风险与对策**：
  - 价格表被改坏 → 用不变量测试兜住，改价必须同时改测试；
  - 厨房列表变长 → 分 3 个分页，每页 ≤ 7 道，短屏（667）也不需要滚动；
  - 仓库面板与每日面板撑爆小屏 → 面板高度固定 800，内容分页，关闭按钮固定在底部。

## 后续

- 仓库按类别排序 / 搜索（货物再多时需要）；
- 套餐与宴席（一次卖多道菜）；
- 花园与水族馆的次要出口（目前它们只产出币，不进仓库）。
