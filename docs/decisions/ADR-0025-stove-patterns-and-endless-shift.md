# ADR-0025：3×3 灶眼图案与无时限营业

- 日期：2026-12-04
- 状态：已接受
- 相关：ADR-0024（餐厅组合台与牧场）、ADR-0023（仓库与餐厅三线）

## 背景

ADR-0024 的组合台是「两样东西叠在一个格子里等计时」。它解决了「一键做菜」，但留下了三个问题：

1. 2 输入配方与 3 输入配方会冲突：先放两件就自动合成，第三件永远加不进去；
2. 营业 90 秒固定局，玩家必须在「做复杂菜」和「赶时间」之间硬取舍，后期内容施展不开；
3. 食物只有「做好 / 糊掉」二元结果，火候没有可读的中间状态。

## 选项

1. 继续 2 输入组合，靠 1.2 秒备齐窗口猜配方；
2. 做完整 3×3 固定格位 shaped 配方（每种配方记具体格子）；
3. 3×3 灶眼 + 2–4 件材料 + 图案类型（相邻 / 三连 / L / 方块 / T），旋转镜像都算；
4. 把灶台做成实时动作小游戏（翻锅、火候条），超出休闲定位。

## 决策

采用选项 3，并配套：

- 5×3 备料台，每格一件；
- 2 个 3×3 灶眼，每个最多 4 件材料；
- 2 件只认相邻，3 件只认三连/L，4 件只认方块/T；同一组材料不同图案可以出不同菜；
- 完整图案后 1.5 秒可升级窗口 / 0.4 秒短确认后自动开火，也可手动开火；
- 出锅后 10–14 秒正好 100%，之后每 5 秒降一档到 75/50/25%，焦炭不能上菜；
- 成品柜锁定品质并暂停焦糊；
- 营业改为无固定时长，客人 1–5 道订单，难度按时间/接待量缓慢提升；打烊正常结算，直接退出按未上菜价值赔偿。

## 后果

- 2/3/4 输入冲突从机制上消失：图案不同，配方不同；
- 配方多样性提高，但不需要记每种配方的固定格位；
- 火候成为可交易的决策：现在上（品质高、收入高）还是先放成品柜/继续做别的；
- 无时限营业需要靠 2 个灶台、3 个客人位、最多 5 道订单与焦糊品质形成软上限，不能再靠 90 秒硬停；
- 餐厅存档升到 v4：`counter` 15 格 + `stoves` 2 个；旧 `craft` 只保留物品 id，旧 `combo-N` 映射到稳定 slug；
- 新增 4 输入深链菜与牧场联动菜，后续加菜必须继续满足「菜价 > 食材、仓卖 < 食材」的反套利约束。
