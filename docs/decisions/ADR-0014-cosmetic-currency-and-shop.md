# ADR-0014：王都币与纯外观小铺

- 状态：已接受
- 日期：2026-11

## 背景

「星尘」原本没有获取/消费闭环。用户希望统一为「王都币」，从游戏中获取，并用于王都建设、角色装扮与图标套；后续排行榜也需要展示玩家名字。

同时项目约束：只做休闲类目，不做 UGC、聊天、抽卡、内购、恋爱叙事；角色装扮不能变成影响公平的数值系统。

## 决策

- `Profile.stardust` 迁移为 `coins`，对外统一叫「王都币」；旧存档自动迁移。
- 获取：三消每局按分数/目标给币；首通、三星、每日挑战额外奖励；失败给少量参与币。
- 消费：
  - 王都建设：喷泉/街灯/花圃三级，纯外观；
  - 国王王后套装：默认礼服 + 花园 + 暖冬 + 星夜；
  - 三消场馆图标：笑脸糖 / 交换糖 / 蜂蜜罐。
- 明确不卖：时间、步数、分数、爆率、道具、抽卡、内购、随机礼盒。
- 玩家名字只从固定词库抽取，不提供自由输入；排行榜只显示名字/分数，不显示 openid。
- 居民只做无名环境 NPC，不显示名字、不可交互、不可换装。

## 审核边界

- 装扮对象仅限固定国王/王后，纯外观、无数值、无剧情、无恋爱叙事；
- 不提供玩家第二角色、自由昵称、上传图片、聊天或陌生人社交；
- 如果后续要做完整换装/角色养成主玩法，应先重新评估类目与审核要求；
- 提审前仍需按微信当前类目与审核口径复核。降级方案：关闭「装扮」页，只保留建设与图标套。

## 后果

- 王都币有了闭合的获取/消费循环；
- 大厅/三消/小铺共享同一套外观数据；
- 名字复用 `players.displayName` 与 `login` 云函数，不新增名字集合或改名函数；排行榜读取当前名字；
- 经济后续可加每日软上限，但不影响本期的纯外观定位。
