# 王都餐厅

> 状态：**可玩原型**（`src/games/restaurant`，分包 `restaurant`）。
> 定位：农场 → 加工屋 → 牧场 → 餐厅这条产业链的**唯一高价出口**；做饭从「点按钮」改成「备料 → 摆图案 → 看火 → 上菜」。

## 1. 三条线

| 页 | 吃什么 | 做什么 | 收益 |
|---|---|---|---|
| 备料台 | **仓库原料**（作物 / 花卉 / 牧产 / 半成品 / 可复用的成菜） | 5×3 备料台摆料，2 个 3×3 灶眼按图案组合、烹饪、控火 | 无，只产出成品 |
| 点菜 | **成品柜**里的菜 / 茶饮 | 客人点单 → 「上菜」 | 菜价 + 繁荣度 |
| 营业 | **本局已解锁原材料** | 无固定时长：客人 1–5 道订单，现做现卖，打烊才结算 | 按菜价 × 品质 + 小费 + 连击结算 |

关键约束：**营业页不读写仓库**。营业只无限供应「清水 + 曾经在农牧场收获过的原材料」，成品只在本局有效；想卖仓库里的货，必须走备料台/灶台 → 成品柜 → 点菜。半成品与成菜不能直接营业供应，必须现做。

## 2. 备料台与灶台（核心玩法）

### 2.1 备料台

- 5×3、15 格，每格只放 **1 件**物品，不叠放、不在格内合成；
- 原料从底部配料区拖入/点一下补位；
- 空间压力来自备料台 15 格、灶眼 9 格、成品柜 6 格。

### 2.2 灶眼图案

每个灶台是 **3×3 灶眼**（9 格）+ 1 个出品位；固定 2 个灶台，最多放 4 件材料。

| 材料数 | 图案 | 说明 |
|---|---|---|
| 2 | 相邻两格（多米诺） | 横/竖都算 |
| 3 | 三连 或 L 形 | 三连横/竖；L 是 2×2 中任意三格 |
| 4 | 2×2 方块 或 T 形 | 旋转/镜像都算 |

- 灶台只在**完整图案**出现时判定配方；2 件只查 2 输入，3 件只查 3 输入，4 件只查 4 输入；
- 同一组材料摆不同图案可以出不同菜：例如 `菌菇高汤 + 挂面 + 鸡蛋` 摆三连是「什锦汤面」，摆 L 形是「三鲜烩面」；
- 图案完成后显示成品预览；还能补第 3/4 件时给 1.5 秒「还可加一件」，不能升级时 0.4 秒短确认后自动开火；也可点「开火」立即开始；
- 摆错图案不消耗材料；3/4 件没有对应配方时不会退回低级配方，拿掉一件重新摆。

### 2.3 烹饪、焦糊与品质

| 状态 | 说明 |
|---|---|
| 备料 | 已摆出部分图案 |
| 备齐 | 图案匹配，等待短确认 |
| 烹饪 | 自动倒计时 |
| 正好 | 出锅 10–14 秒内，品质 100% |
| 微焦 | 再过 5 秒，品质 75% |
| 焦 | 再过 5 秒，品质 50% |
| 糊 | 再过 5 秒，品质 25% |
| 焦炭 | 再过 5 秒，品质 0%，不能上菜，点掉清焦 |

- 正好窗口：2 输入 10 秒、3 输入 12 秒、4 输入 14 秒；之后每 5 秒降一档；
- 上菜结算 = `菜品价 × 品质`；小费也乘平均品质；品质 <50% 没有小费、连击归零；
- 成品柜锁定当前品质并暂停继续焦糊；营业里成品柜的菜可拖回灶台当深链输入，品质不继承；
- 焦炭不额外扣钱，清掉后可回收 **1 份饲料**；厨房直接入仓库，营业先记账，打烊时统一入仓库；结算统计焦糊次数、平均品质与回收饲料。

## 3. 配方与深链菜

`src/games/restaurant/data/combos.ts`，共 **56 条**配方，覆盖 **33 道菜 + 10 款茶饮**与全部半成品。

- 2 输入：相邻两格；3 输入：三连/L；4 输入：方块/T；
- 新增 3 输入：蔬菜焖饭、洋葱土豆饼、家常豆腐、草莓豆沙糕、玫瑰鲜花饼、桂花米糕、羊肉菌菇汤；
- 新增同材料不同图案：什锦汤面（三连）/ 三鲜烩面（L）；
- 新增 4 输入深链：砂锅全家福（方块，6 步）、四宝汤面（T 形，7 步，牧场联动）；
- 新增牧场联动：卤肉面（猪肉高汤 + 挂面，5 步）、四宝汤面只进厨房/点菜，不进营业无限供应；
- 补齐独占原材料：萝卜糕（白萝卜 + 面粉，菜价 110）、拍黄瓜（黄瓜 + 蒜蓉，160）；
- 新增 5 款花茶：雏菊茶 45、郁金香茶 80、向日葵茶 105、风信子茶 195、荷花茶 245；
- `recipeSteps()` 递归统计一盘菜需要几次灶台操作；`SHIFT_ORDER_POOL` 只收当前解锁供应能递归做出来、步数 1–6 的菜。

## 4. 点菜

- 3 张固定桌，每桌一道菜；
- 上菜消耗 1 份成品 → 加菜价 + 繁荣度；
- 没有耐心条、没有失败，缺成品就回备料台/灶台做一份；
- 页面底部「成品柜」列出所有有库存的成品；
- 点菜按标准品质结算；营业才按火候品质结算；
- 每日点菜目标：累计上 8 道，奖励 150 王都币 +3 繁荣；跨天自动重置，页面同时显示营业最佳成绩。

## 5. 营业（无时限）

- 3 个客人位，客人订单 **1–5 道菜/饮品**；同一道菜可以点多份；
- 逐道上菜，全部上齐后用餐付款；付款 = `Σ(菜价 × 品质)` + 道数奖励 + 连击 + 小费；
- 部分上菜后超时：已上菜按 `50% × 品质` 结算，未上菜不结算，连击归零；
- 品质 <50% 没有小费、连击归零；焦炭不能上菜；
- 没有固定时长；只有「打烊」或直接退出才结束；
- 难度按 `tier = min(5, floor(elapsed/150s) + floor(已接待客人/20))` 缓慢提升；前 3 位客人固定 1 道、1–2 步；
- 单道菜配方步数档位：1–2 步 30%、3 步 40%、4 步 25%、5+ 步 5%；5+ 始终稀有，难度主要靠订单道数增加；
- 订单道数随 tier 从 1 道慢慢升到最多 5 道；上客间隔 8 秒 → 5 秒，有下限；耐心按订单总步数与道数计算；
- 供应解锁：新号只有**清水**；农场 18 种作物、花园 9 种花卉、牧场 4 种产物各自在**第一次收获/收取**时永久解锁，之后营业无限供应对应原材料；一旦解锁，卖光库存也不会回退；
- 半成品（面粉/挂面/蒜蓉等）与成菜/茶饮不进入无限供应，必须在备料台/灶台现做；
- 订单池按当前已解锁原材料递归生成，做不出任何菜时禁止开张并提示先去农牧场收获；
- 供应轨横向滑动：两行 × 7 列可视窗口，清水 → 已解锁原材料 → 未解锁原材料（灰显加锁）；横向滑动滚动，向备料台/灶台方向拖动才是拿料；左右小箭头与滚动条作为兜底；
- 打烊改为「打烊中」：不再新增客人，服务完当前客人自动结算；没有流失且客人清空时显示「完美打烊」，罚款 0；
- 打烊中客人流失：罚款 = `round(未上菜菜品总价 × 30%)`，只影响本局净收入；
- 直接退出/返回：罚款 = 已累计打烊罚款 + `5 × 剩余未上菜客人数 + round(剩余未上菜菜品总价 × 30%)`；净收入 = 营业额 - 罚款，**可以为负**；
- 结算只应用一次净收入：净收入为负时从王都币扣，钱包最低扣到 0，不会出现负数；
- 结算评分 = 服务率 + 收入效率综合 S/A/B/C，不再按总收入（无时限会失真）。

## 6. UI

- 顶部：返回 / 标题 / 王都币；页签（备料台 / 点菜 / 营业）；
- 备料台：分类页签（农产 / 牧产 / 加工，清水归在农产）+ 提示条 + 5×3 备料台 + 2 个 3×3 灶台 + 半透明建议条 + 无限/仓库配料区；
- 营业：状态条 + 3 个客人卡（1–5 道订单图标）+ 6 格成品柜 + 2 个 3×3 灶台 + 建议条 + 5×3 备料台 + 两行横向滑动供应轨（未解锁灰显）；
- 拖拽时有货物幽灵；轻点也支持「点原料补位」「点成品柜自动匹配客人」「点配料再点客人」；
- 建议卡显示产物、配方文本、3×3 图案预览；空灶台会同时画出半透明摆法 ghost，并过滤当前供应做不出的组合；拖动成品菜时显示按品质预计收入；
- 出锅品质用蒸汽颜色/烟量分档，收取时按品质变调；焦炭有独立暗烟与失败音；
- 统一纸雕 UI，货物图形与仓库/农场/牧场共用。

## 7. 经济

- 只花王都币，不引入第二种货币；
- 菜价 > 食材卖价之和；成菜仓卖 = 菜价四折且低于食材之和（见 [economy-loop.md](./economy-loop.md)）；
- 备料台/灶台不再提供「一键补齐」：缺什么就去农场/牧场/加工屋生产，或去仓库卖货换币；
- 营业发的是本局收入，不消耗库存，也不产出库存；所有 crop / flower / ranch 原材料在首次收获后进入营业无限供应，processed/drink/dish 仍必须现做；
- 王都仓库的原材料格会显示「营业」小标记，方便知道哪些货已经能用于营业；
- 排行榜 id `restaurant`，分数 = 累计点菜营业额 + 营业最好成绩，覆盖两条产出线。

## 8. 存档

```ts
interface RestaurantSave {
  schemaVersion: 6;
  tables: string[];         // 3 张桌当前的菜（菜单 id）
  nextItem: number;         // 下一张桌的菜单轮转
  cooked: number;           // 累计备菜份数
  served: number;           // 累计上菜
  totalCoins: number;       // 累计点菜营业额
  bestRevenue: number;      // 营业最好成绩
  bestCombo: number;
  shifts: number;           // 营业局数
  perfectCloses: number;    // 完美打烊次数（只记录，不发货币）
  counter: (string|null)[]; // 15 格备料台，每格一件
  stoves: StoveState[];     // 2 个 3×3 灶台（含烹饪/出锅品质）
  discovered: string[];     // 已发现配方 slug
  dailyDate: string;        // 当日日期
  dailyServed: number;      // 当日点菜上架数
  dailyClaimed: boolean;    // 当日目标奖励是否已领
}
```

- key：`save:restaurant`；
- v3 → v4：旧 `craft` 只保留物品 id 放进备料台，计时丢弃；旧 `combo-N` 映射到稳定 slug；
- v4 → v5：补点菜每日目标字段；
- v5 → v6：补 `perfectCloses`；旧存档按 0 处理；
- 营业状态只在内存中，不写入存档；退出/切场景前必须结算；
- 原料、成品都在 `profile.pantry`；营业成品不写仓库；营业供应解锁记录在 `profile.ingredientUnlocks`（profile v8）。

## 10. 合规

- 只做组合、上菜、端盘子；无雇佣/真实货币叙事；
- 无 UGC、无聊天、无陌生人社交、无内购、无抽卡；
- 食材只能靠种、靠牧场、靠加工，不能用真实货币买；
- 不出现恋爱/情侣/交友文案。
